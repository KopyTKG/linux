A **filesystem** turns a raw block device (a long row of numbered blocks) into files and directories with names, permissions and timestamps. Linux supports many filesystems through one common layer, the **VFS** (Virtual File System), so `cat`, `ls` and `cp` work the same on ext4, btrfs, FAT or even [[proc]].

```bash
cat /proc/filesystems     # what this kernel supports right now (nodev = no disk needed)
findmnt -rno FSTYPE | sort | uniq -c    # what is mounted
```

# Core concepts

| Concept        | What it is                                                                 |
| -------------- | -------------------------------------------------------------------------- |
| **Block**      | Smallest allocation unit, usually 4 KiB. A 1-byte file still uses one block. |
| **Inode**      | Record describing one file: type, permissions, owner, size, timestamps, link count, where its data blocks are. **Not** the name. |
| **Directory**  | A special file that maps **names → inode numbers**.                        |
| **Superblock** | Filesystem-wide info: size, block size, free counts, UUID, label, state. Several backup copies exist. |
| **Journal**    | Log of pending metadata changes. After a crash the filesystem replays it instead of scanning everything. |
| **Extent**     | "Blocks 1000–1999 belong to this file" in one record instead of 1000 entries. |
| **CoW**        | Copy-on-write: never overwrite in place; write new data elsewhere and switch pointers (btrfs, ZFS). |

```bash
ls -i file.txt            # inode number
stat file.txt             # inode details: size, blocks, links, times
df -i                     # inodes used/free per filesystem → [[disk-usage]]
```

> [!info] Names live in directories, not in files
> That's why **hard links** work: two names in directories pointing to the same inode (`ln a b`, link count = 2). The data is freed only when the link count is 0 **and** no process has the file open → [[disk-usage]] "deleted but open".
> Hard links can't cross filesystems because inode numbers are only unique within one filesystem. Symlinks (`ln -s`) store a path and can point anywhere.

# Comparison

| FS        | Type            | Journal / safety       | Max file / volume  | Snapshots | Compression | Shrink | Typical use                               |
| --------- | --------------- | ---------------------- | ------------------ | --------- | ----------- | ------ | ----------------------------------------- |
| **ext4**  | Classic Linux   | Journal                | 16 TiB / 1 EiB     | No        | No          | Yes (offline) | Safe default for `/`, `/home`, servers |
| **xfs**   | High-performance| Journal                | 8 EiB / 8 EiB      | No        | No          | **No** | Big files, servers, parallel I/O          |
| **btrfs** | CoW             | CoW + checksums        | 16 EiB / 16 EiB    | **Yes**   | **Yes** (zstd, lzo, zlib) | Yes (online) | Desktops with snapshots, NAS → [[btrfs]] |
| **f2fs**  | Flash-friendly  | Checkpoints            | ~3.9 TiB / 16 TiB  | No        | Yes         | Limited| SD cards, phones, flash                   |
| **vfat**  | FAT32           | None                   | **4 GiB** / 2 TiB  | No        | No          | Yes    | ESP, small USB sticks, compatibility      |
| **exfat** | FAT successor   | None                   | 16 EiB / 128 PiB   | No        | No          | No     | USB sticks/SD cards shared with Windows/macOS |
| **ntfs**  | Windows         | Journal                | 16 TiB+ / 256 TiB  | (VSS on Windows) | Yes  | Yes    | Dual boot data disks (`ntfs3` kernel driver) |
| **tmpfs** | RAM             | None (gone on reboot)  | RAM + swap         | No        | No          | Live   | `/tmp`, `/run`, `/dev/shm` → [[tmp]], [[run]] |

> [!note] Linux permissions on foreign filesystems
> vfat and exfat have **no Unix owners or permissions**. Owner and mode are faked at mount time with options like `uid=1000,gid=1000,umask=022`. `chmod` on them does nothing (or fails).

Not on any disk, generated by the kernel:

| FS          | Mounted at          | Note          |
| ----------- | ------------------- | ------------- |

| `sysfs`     | `/sys`              | [[sys]]       |
| `devtmpfs`  | `/dev`              | [[dev]]       |
| `tmpfs`     | `/run`, `/tmp`, `/dev/shm` | [[run]], [[tmp]] |
| `cgroup2`   | `/sys/fs/cgroup`    | [[sys]]       |

# Inspecting a filesystem (read-only)

```bash
lsblk -f                              # FSTYPE, LABEL, UUID, FSAVAIL, FSUSE%
findmnt -no FSTYPE,OPTIONS /          # type and mount options of /
stat -f /                             # block size, total/free blocks and inodes
sudo blkid /dev/nvme0n1p3             # TYPE, UUID, LABEL from the superblock
sudo tune2fs -l /dev/sda1             # ext4 superblock: features, mount count, last check
sudo dumpe2fs -h /dev/sda1            # same, header only
xfs_info /data                        # xfs geometry (works on mounted path)
sudo btrfs filesystem show            # btrfs devices → [[btrfs]]
```

`stat -f /` example:
```
  File: "/"
    ID: 1a2b3c4d5e6f7a8b Namelen: 255     Type: btrfs
Block size: 4096       Fundamental block size: 4096
Blocks: Total: 241827328  Free: 98765432   Available: 97654321
Inodes: Total: 0          Free: 0
```
btrfs shows `0` inodes because it creates them dynamically — it never runs out.

# Creating and repairing

> [!danger] `mkfs` erases everything on the target
> `mkfs` writes a **new empty filesystem**. All existing data on that partition is gone instantly. `fsck` repair on a **mounted** filesystem can corrupt it.
> Before running: `lsblk -f` → confirm device by size, model and current FSTYPE; make sure it's **not mounted**; have a backup.
> ```bash
> sudo mkfs.ext4 -L Data /dev/sdX1          # new ext4 with label
> sudo mkfs.xfs  -L Data /dev/sdX1
> sudo mkfs.btrfs -L Data /dev/sdX1
> sudo mkfs.vfat -F 32 -n EFI /dev/sdX1     # ESP / USB stick
> sudo mkfs.exfat -n STICK /dev/sdX1
> sudo mkswap /dev/sdX2                      # → [[swap]]
>
> sudo fsck -n /dev/sdX1                     # -n = check only, change nothing
> sudo e2fsck -f /dev/sdX1                   # ext4 repair (unmounted!)
> sudo xfs_repair /dev/sdX1                  # xfs repair (unmounted!)
> sudo e2label /dev/sdX1 NewName             # rename (harmless)
> sudo resize2fs /dev/sdX1                   # grow/shrink ext4 to partition size
> ```

# Scripting recipes

### Filesystem type of any path
```bash
stat -f -c %T /home/alice      # btrfs
findmnt -no FSTYPE --target /home/alice
```

### Is a path on the same filesystem as another? (can I hard-link / mv instantly?)
```bash
[[ $(stat -c %d /home/alice) == $(stat -c %d /tmp) ]] && echo same || echo different
```

### Count mounted filesystems by type
```bash
findmnt -rno FSTYPE | sort | uniq -c | sort -rn
```

### List only real (disk-backed) filesystems
```bash
findmnt -rno TARGET,SOURCE,FSTYPE | awk '$2 ~ "^/dev/"'
```

### Check a FAT stick can hold a big file
```bash
f=movie.mkv; dst=/run/media/alice/STICK
[[ $(stat -f -c %T "$dst") == msdos && $(stat -c %s "$f") -ge $((4*1024**3)) ]] \
  && echo "Too big for FAT32 (4 GiB limit)"
```
