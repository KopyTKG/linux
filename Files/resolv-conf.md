`/etc/resolv.conf` tells the C library **which DNS servers to ask**. Every program that resolves names through glibc reads it. On modern systems you rarely write it yourself: a network manager or `systemd-resolved` generates it.

> [!info] Quick facts
> - Path: `/etc/resolv.conf` · mode `0644`
> - Often a **symlink** or a **generated** file. The first comment line usually says who wrote it
> - Example: a real file, first line `# Generated by NetworkManager`, pointing to `nameserver 127.0.0.53` (the local `systemd-resolved` stub)
> - Manual: `man 5 resolv.conf`

> [!warning] Hand edits get overwritten
> If something generates this file, your change is gone after the next reconnect or reboot. Change DNS in the tool that owns it (NetworkManager, `resolvectl`/`/etc/systemd/resolved.conf`, netplan, DHCP client) → [[dns]], [[network-manager]].

# Format

```
nameserver 127.0.0.53
options edns0 trust-ad
search home.lan
```

| Keyword       | Example                  | Meaning                                                           |
| ------------- | ------------------------ | ----------------------------------------------------------------- |
| `nameserver`  | `1.1.1.1`                | DNS server IP. Up to **3**, asked in order (next only on timeout) |
| `search`      | `home.lan corp.example`  | Domains appended to short names: `ping nas` → `nas.home.lan`      |
| `domain`      | `home.lan`               | Old single-domain form of `search`                                |
| `options`     | `edns0 trust-ad`         | Resolver options (table below)                                    |

| Option         | Meaning                                                         |
| -------------- | --------------------------------------------------------------- |
| `ndots:N`      | Names with fewer than N dots try `search` domains first (default 1) |
| `timeout:N`    | Seconds before trying the next server (default 5)               |
| `attempts:N`   | Rounds through the server list (default 2)                      |
| `rotate`       | Spread queries across servers instead of always the first       |
| `edns0`        | Allow bigger DNS answers                                        |
| `trust-ad`     | Trust the "authenticated data" (DNSSEC) flag from the server    |

# Who owns it? The common setups

| What you see                                          | Owner                                    |
| ----------------------------------------------------- | ---------------------------------------- |
| Symlink → `/run/systemd/resolve/stub-resolv.conf`, `nameserver 127.0.0.53` | `systemd-resolved` (stub mode) |
| Symlink → `/run/systemd/resolve/resolv.conf`          | `systemd-resolved`, real upstream servers listed |
| `# Generated by NetworkManager`                       | NetworkManager                           |
| `# Generated by resolvconf` / `/run/resolvconf/...`   | `resolvconf` / `openresolv`              |
| Plain file, no comment                                | Written by hand or by the installer      |

> [!tip] `127.0.0.53` means "ask systemd-resolved"
> The real upstream servers are then not in this file. See them with `resolvectl status` or `resolvectl dns`.

# Scripting recipes

### DNS servers glibc will use
```bash
awk '$1=="nameserver" {print $2}' /etc/resolv.conf
```

### Who manages the file?
```bash
ls -l /etc/resolv.conf
readlink -f /etc/resolv.conf
head -1 /etc/resolv.conf
```

### Real upstream servers behind the stub
```bash
resolvectl dns 2>/dev/null || grep nameserver /run/systemd/resolve/resolv.conf
```

### Test resolution through the normal path vs one server
```bash
getent hosts example.com          # what programs see (hosts file + DNS)
dig +short example.com @1.1.1.1   # ask one DNS server directly (if dig is installed)
```
